Pymunk¶

Pymunk physics integration for Manim.

This module provides physics simulation capabilities using Pymunk, including rigid body dynamics, constraints, and custom mobjects.

class manim_extensions.pymunk.Apple(**kwargs)[source]¶

An apple-shaped Mobject built from Bezier curves.

Parameters:

**kwargs (Any) – Forwarded to the parent VMobject.

Examples

Example: AppleScene ¶

import numpy as np
from manim import *
from manim_extensions.pymunk import *

class AppleScene(Scene):
    def construct(self):
        apples = VGroup(
            Apple(color=RED, fill_color=RED, fill_opacity=0.6),
            Apple(color=GREEN, fill_color=GREEN, fill_opacity=0.6),
            Apple(color=YELLOW, fill_color=YELLOW, fill_opacity=0.6),
        )
        apples.arrange(RIGHT, buff=0.6).scale(0.8)
        self.add(apples)
class manim_extensions.pymunk.Gear(num_teeth=12, radius=1.0, tooth_height=0.4, width_factor=0.5, roundness=0.05, hole_radius=0.1, **kwargs)[source]¶

A gear-shaped Mobject with teeth and an optional center hole.

Parameters:

  • num_teeth (int) – The number of teeth distributed around the gear.

  • radius (float) – The radius of the base disc of the gear.

  • tooth_height (float) – The height of each tooth, measured from the base disc outward.

  • width_factor (float) – The ratio of tooth width to the space available for a single tooth. (half tooth, half gap).

  • roundness (float) – The corner rounding radius applied to each tooth. Set to 0 for sharp corners.

  • hole_radius (float) – The radius of the hole cut out of the gear’s center. Set to 0 for a solid gear.

  • **kwargs (Any) – Forwarded to the parent VMobject.

Examples

Example: PymunkGear ¶

from manim import *
from manim_extensions.pymunk import *

class PymunkGear(Scene):
    def construct(self):
        gears = VGroup(
            Gear(num_teeth=8, radius=0.8, color=BLUE),
            Gear(num_teeth=12, radius=1.0, tooth_height=0.5, color=GREEN),
            Gear(num_teeth=16, radius=0.9, hole_radius=0, color=RED),
        )
        gears.arrange(RIGHT, buff=0.8)
        self.add(gears)
class manim_extensions.pymunk.SpaceScene(gravity=(0, -9.81), **kwargs)[source]¶

A scene that hosts and manages a Pymunk physics simulation.

When the actual relative angle deviates from the target angle, the spring torque pulls it back; the damping torque dampens the oscillation.

Parameters:

  • gravity (tuple[float, float]) – The gravity acceleration vector \((g_x, g_y)\) applied to the physical space.

  • **kwargs (Any) – Forwarded to the parent ZoomedScene.

Examples

Example: SpaceSceneUsage ¶

from manim import *
from manim_extensions.pymunk import *

class SpaceSceneUsage(SpaceScene):
    def construct(self):
        # a floor and three balls driven by the Pymunk physics space
        floor = Line(LEFT * 6, RIGHT * 6, stroke_width=8, color=GREY)
        floor.to_edge(DOWN, buff=0.5)
        balls = VGroup(*[
            Circle(radius=0.3, color=BLUE, fill_opacity=0.8).move_to(
                UP * 3 + (i - 1) * RIGHT
            )
            for i in range(3)
        ])
        self.play(FadeIn(floor), FadeIn(balls))
        self.add_static_body(floor)
        self.add_dynamic_body(*balls)
        self.add_shapes_filter(*balls, group=1)
        self.apply_impulse_at_world_point(
            balls[0], impulse=(4, 2, 0), point=tuple(balls[0].get_center())
        )
        self.wait(5)
        Group(*self.mobjects).scale(0.08).move_to(ORIGIN)

add_shapes_filter(*mobs, group=0, categories=4294967295, mask=4294967295)[source]¶

Sets the collision filter for the shapes associated with the given Mobjects. This determines which shapes can collide with each other based on groups, categories, and masks.

Parameters:

  • mobs (Mobject) – The Mobjects whose physical shapes will have the filter applied.

  • group (int) – A group ID. Shapes in the same non-zero group do not collide. Useful for creating multi-part objects where internal parts ignore each other.

  • categories (int) – A bitmask of the categories this shape belongs to.

  • mask (int) – A bitmask of the categories this shape can collide with.

Return type:

None

add_static_body(*mobs, family_members=False, is_solid=True, elasticity=0.8, friction=0.8, density=1.0, sensor=False, surface_velocity=(0.0, 0.0), center_of_gravity=(0.0, 0.0), velocity=(0.0, 0.0), angular_velocity=0.0)[source]¶

Adds Mobjects to the physical space as static bodies. Static bodies do not move under the influence of gravity or collisions and are typically used for environment boundaries like floors and walls.

Parameters:

  • mobs (Mobject) – The Mobjects to be treated as static physical objects.

  • family_members (bool) – If True, all sub-mobjects (children) will also be added to the physical space.

  • is_solid (bool) – Determines if the body is solid. If False, it might be treated as a hollow boundary or wireframe depending on the implementation.

  • elasticity (float) – The elasticity (restitution) of the shape. A value of 0.0 means no bounce, while 1.0 represents a perfectly elastic collision.

  • friction (float) – The friction coefficient. Determines how much the object resists sliding along surfaces.

  • density (float) – The density of the object. For static bodies, this is primarily used to calculate mass if the body is ever converted to dynamic.

  • sensor (bool) – If True, the shape will detect collisions but will not produce a physical collision response (objects will pass through it).

  • surface_velocity (tuple[float, float]) – The surface velocity of the shape. Useful for creating conveyor belt effects.

  • center_of_gravity (tuple[float, float]) – The center of gravity relative to the Mobject’s center.

  • velocity (tuple[float, float]) – The initial linear velocity of the body. Though static, this can affect how objects bounce off it.

  • angular_velocity (float) – The initial angular velocity of the body.

Return type:

None

active_body(*mobs)[source]¶

Activates the physical bodies of the given Mobjects if they are sleeping. In physics simulations, bodies that have come to rest are often put to ‘sleep’ to save computation. This method forces those bodies back into an active state.

Parameters:

mobs (Mobject) – The Mobjects whose associated physical bodies should be activated. This includes all sub-mobjects within the family tree of each provided Mobject.

Return type:

None

sleep_body(*mobs)[source]¶

Forces the physical bodies of the given Mobjects into a sleeping state. Sleeping bodies are removed from the physics simulation update loop until they are touched by another active body or manually activated, which helps reduce CPU usage.

Parameters:

mobs (Mobject) – The Mobjects whose associated physical bodies should be put to sleep. This iterates through all sub-mobjects within the family tree of each provided Mobject.

Return type:

None

draw_debug_img(option=None, xlim=(-8, 8), ylim=(-5, 5))[source]¶

manim-pymunk integrates the Pymunk 2-D physics engine with Manim. It provides a physics Space mobject, a dedicated SpaceScene with step-simulation support, and a collection of visual constraint and mobject classes (springs, pin joints, gears, etc.).

The code is bundled inside manim_extensions as the pymunk subpackage.

Features¶

  • SpaceScene – a ZoomedScene subclass that steps the physics engine on each frame.

  • VSpace – the physics space mobject that holds bodies, shapes, and constraints.

  • Visual constraints: VPinJoint, VPivotJoint, VDampedSpring, VGearJoint, VGrooveJoint, VRotaryLimitJoint, VSlideJoint, VSimpleMotor, VRatchetJoint, VDampedRotarySpring.

  • Custom mobjects: VSpring, Apple, Gear.

Usage¶

Upstream shipped manim-pymunk on PyPI; here it is bundled inside pymunk. Write a scene subclassing SpaceScene, build ordinary Manim mobjects, register them as static or dynamic bodies, optionally set collision filters and constraints, and play — the scene steps the Pymunk space on every frame.

Example: VPivotJointScene ¶

from manim import *
from manim_extensions.pymunk import SpaceScene
from manim_extensions.pymunk.constraints import VPivotJoint

class VPivotJointScene(SpaceScene):
    def construct(self):
        static_dot = Dot(ORIGIN)
        square = Square().move_to(static_dot)
        square2 = Square().move_to(static_dot.get_center() + UP * 2).scale(0.5)
        constraints = [
            VPivotJoint(static_dot, square),
            VPivotJoint(square, square2, pivot_world=UP * 3),
        ]
        self.play(FadeIn(static_dot), FadeIn(square), FadeIn(square2))

        # register the physics bodies (shapes, mass, angle, ...)
        self.add_static_body(static_dot)
        self.add_dynamic_body(square, square2, angular_velocity=PI * 2)

        # collision filter: which bodies may collide
        self.add_shapes_filter(static_dot, square, square2, group=2)

        # add the visual constraints, then step the simulation
        self.add_constraints(*constraints)
        self.wait(3)
        Group(*self.mobjects).scale(0.8).move_to(ORIGIN)

References: SpaceScene VPivotJoint

Important

Once an object is under physics control, any Manim animation on it steps the simulation until the object is removed from the physics space (or the scene updater is removed).

The scene also exposes collision filtering, collision-type and wildcard collision handlers, force and impulse application, position / velocity query helpers, and a Matplotlib debug draw of the space.

How it works¶

The scene class subclasses ZoomedScene and owns a VSpace physics mobject. Each mobject runs an internal updater that copies Pymunk state back onto the visual; body, shapes and angle are attached as mobject attributes. Collision shapes are generated automatically from Manim geometry: solid shapes become polygons, hollow shapes are built from line segments, non-convex shapes are decomposed, and image shapes are extracted from pixel contours. Elasticity, friction, density, sensor flags and collision callbacks are all configurable on the body-adding calls, with sensible defaults provided.
